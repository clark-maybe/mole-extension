# 销售线索工作台

Options 默认进入 `#/workspace`。会话链接采用 `#/workspace/<sessionId>`，侧栏顶部的打开入口可带着当前会话进入工作台。

找客默认交付可追溯的线索表。CRM 只是一种可选录入渠道，不提供企业或联系人查询，也不是任务的必经步骤；只有用户要求录入该目的地时才使用。当前接入指定公司的螳螂 CRM，其他录入渠道可后续追加。

## 使用流程

1. 在模型设置中配置可用模型，在渠道页面打开并登录所需平台。
2. 描述行业、地区、数量和核验条件。Agent 可启动平台作业，结果按批次保存；工作台关闭后作业继续由后台管理。
3. 在线索库查看字段、原始证据、采集步骤、符合性判断与条件版本。平台账号和企业主体分别保存，主体候选可以附依据人工确认。
4. 导出整个任务或整个线索库的 CSV。CSV 包含判断、条件版本、法人、联系电话、来源和证据标识；包含待核验记录，应根据判断列筛选。
5. 需要录入螳螂 CRM 时，绑定目标公司、账号与字段配置，填写运行时验证参数，并在会话中明确录入目标。只有同会话当前条件下符合的企业可以提交。不使用此渠道时无需配置 CRM。

工作台与已有对话共用用户气泡和执行过程组件，正文使用已有 Markdown 渲染器。连续工具调用默认折叠；对话区独立滚动，输入区固定在下方。阅读旧消息时不强制跳到底部，加载更早历史时保持阅读位置。

## 保存与恢复

- IndexedDB `mole_workspace` 保存完整会话档案、任务、证据、事实、判断、主体关联、交付回执和指令。Chrome Storage 保存设置和旧版兼容缓存。
- 每个采集批次在一个事务内保存证据、线索、字段事实、任务关联、步骤和游标；写入失败不推进游标。稳定来源标识用于线索去重，执行代次用于拒绝过期回包。
- 对话输入在模型排队前保存。模型主编排串行执行，新会话不会取消旧会话；执行中追加的输入由目标会话在下一轮接收。
- 后台重启会恢复已授权的只读平台作业。模型回合显示为中断，可从保存状态继续；原始读取回包没有保存时不会冒充已完成的后台作业。
- 旧版因要求 CRM 登录而等待的企业与联系人查询会重新排队；人工暂停、取消以及平台自身的登录等待保持原状态。
- 抖音登录或验证处理完后，观察器按任务、执行代次和页签核对后唤醒任务。人工暂停、取消的任务不会因此继续。其他渠道处理完登录后使用任务“继续”。
- 问题和授权按请求标识保存，页面刷新可继续回答。后台已重启的旧请求标记为中断，继续会话时需要重新建立交互。
- CRM 先保存目标身份、字段快照与录入意图，再标记发送。回执丢失进入 `unknown`，人工核对或晚到回执确认后才能接续。已确认成功、重复或明确失败的回执不会被晚到的不明结果覆盖。
- 数据库不可写时停止依赖持久化的执行。处理容量等问题后重新加载扩展，由已提交检查点恢复。

## 当前边界

- 抖音批量采集复用当前项目的登录态分页接口，目标为 1–999 条、批次间隔至少 10 秒，并同时识别两种企业认证字段。未加入旧版前台滚动采集的兜底路径。
- 励销云、风鸟云保留旧版首屏 10 条范围，更多命中会标记部分完成。企业查询和联系方式查询只依赖各平台自身登录态，与 CRM 独立。
- 企业认证只用于发现候选；主营业务、地区、企业主体及符合性仍需证据。电话不会被自动认定为法人的个人电话。
- 旧版只有摘要或截断缓存的会话标记为 `legacy_partial`，无法补回此前未保存的内容。
- 完整 JSON 备份包含业务关联，导入按记录标识补齐缺失数据，不覆盖本机已有记录，导入任务保持暂停。当前备份整包在内存中生成，单次导入上限 64 MB；大数据量的流式备份尚待扩展。验证参数不进入业务备份。
- 已预留稳定 ID、版本、事件序号和元数据入口；服务端同步尚未实现。
- 自动化测试使用 IndexedDB 与浏览器 API 模拟，不等同于真实平台登录态、验证码和 CRM 业务联调。视图检查由项目负责人进行。
