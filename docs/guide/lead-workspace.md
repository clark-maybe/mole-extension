# 销售线索工作台

Options 默认进入 `#/workspace`。会话链接采用 `#/workspace/<sessionId>`，侧栏顶部的打开入口可带着当前会话进入工作台。

找客默认交付可追溯的线索表。CRM 只是一种可选录入渠道，不提供企业或联系人查询，也不是任务的必经步骤；只有用户要求录入该目的地时才使用。当前接入指定公司的螳螂 CRM，其他录入渠道可后续追加。

当前企业信息渠道仅启用励销云。抖音等内容平台用于发现活跃企业，需检查近期发布内容、时间和经营证据；明确企业名称和主体后，再通过励销云精确补全工商信息、法人及手机号。用户已提供企业名称时可以直接补全。风鸟云入口与 Agent 工具暂时停用，旧数据保留。

## 使用流程

1. 在模型设置中配置可用模型，在渠道页面打开并登录所需平台。
2. 描述行业、地区、数量、活跃要求和核验条件。Agent 先在内容平台发现线索、验证活跃与经营情况，再明确企业主体并用励销云补全。结果按批次保存；工作台关闭后作业继续由后台管理。
3. 在线索库打开企业档案，查看可复制的电话/邮箱、Agent 整理的企业概览、业务匹配和工商资料。来源与整理历史可按需展开，平台账号和企业主体分别保存。
4. 导出整个任务或整个线索库的 CSV。CSV 包含业务判断、条件版本、法人、全部联系方式、Agent 摘要与跟进建议、来源和证据标识；包含尚未评估业务匹配的记录，可按判断列筛选。
5. 需要录入螳螂 CRM 时，绑定目标公司、账号与字段配置，填写运行时验证参数，并在会话中明确录入目标。只有同会话当前条件下符合的企业可以提交。不使用此渠道时无需配置 CRM。

工作台与已有对话共用用户气泡和执行过程组件，正文使用已有 Markdown 渲染器。连续工具调用默认折叠；对话区独立滚动，输入区固定在下方。阅读旧消息时不强制跳到底部，加载更早历史时保持阅读位置。

会话列表将“正在推进”和“待处理与暂停”独立置顶，可筛选进行中或待处理会话。状态同时考虑模型和后台作业，模型回合结束但采集仍在执行时不会显示为结束；历史分页也不会隐藏旧会话的后台任务。当前会话顶部显示实时执行条、真实作业计数和暂停/继续入口。绿色波形表示执行，虚线环表示排队，琥珀色表示需要处理；系统减少动态效果设置会关闭动画。

## 企业档案与联系方式

- 励销云返回的联系方式默认可信，可直接用于销售联系；不再要求二次核实号码真实性或归属。联系人姓名与职位按来源显示，未单独标记法人手机不会使其他电话失效。旧励销云记录同样适用。
- 详情按联系方式、企业概览、业务匹配和工商资料分区。电话、邮箱可逐项或全部复制，成立日期等字段使用可读格式；没有关联企业或录入记录时不展示空区块。
- Agent 在补全后调用 `lead_workspace(action="save_profile")` 自动填写企业简介、主营业务、地区、活跃情况、跟进建议和标签，引用线索证据与事实。档案写入本地库后自动刷新页面，无需手填表单。
- 档案与来源原值分别保存。每次整理追加版本；过期版本写入需重新读取，不静默覆盖。最近 30 版可在详情查看，完整历史随备份保存。
- 原始字段、技术标识、采集证据、字段事实、整理和判断历史都在折叠追溯区，仍可回到来源会话。联系方式可信与业务是否符合条件分别显示；业务条件变更不会影响联系方式的可信状态。

## 保存与恢复

- IndexedDB `mole_workspace` 保存完整会话档案、任务、证据、事实、判断、主体关联、交付回执和指令。Chrome Storage 保存设置和旧版兼容缓存。
- 每个采集批次在一个事务内保存证据、线索、字段事实、任务关联、步骤和游标；写入失败不推进游标。稳定来源标识用于线索去重，执行代次用于拒绝过期回包。
- 励销云精确查询唯一同名主体后，先保存企业信息与联系人检查点，再自动获取联系方式。重启可从联系人步骤接续，不重复查询企业；名称不明确或重名时只保存候选，待核实后继续。法人手机号使用平台联系人姓名/法人角色标记归属，单独保存 `legalPersonPhone` 和对应证据路径；普通企业电话保留为联系电话。
- 对话输入在模型排队前保存。模型主编排串行执行，新会话不会取消旧会话；执行中追加的输入由目标会话在下一轮接收。
- 后台重启会恢复已授权的只读平台作业。模型回合显示为中断，可从保存状态继续；原始读取回包没有保存时不会冒充已完成的后台作业。
- 旧版因要求 CRM 登录而等待的企业与联系人查询会重新排队；人工暂停、取消以及平台自身的登录等待保持原状态。
- 抖音登录或验证处理完后，观察器按任务、执行代次和页签核对后唤醒任务。人工暂停、取消的任务不会因此继续。其他渠道处理完登录后使用任务“继续”。
- 问题和授权按请求标识保存，页面刷新可继续回答。后台已重启的旧请求标记为中断，继续会话时需要重新建立交互。
- CRM 先保存目标身份、字段快照与录入意图，再标记发送。回执丢失进入 `unknown`，人工核对或晚到回执确认后才能接续。已确认成功、重复或明确失败的回执不会被晚到的不明结果覆盖。
- 数据库不可写时停止依赖持久化的执行。处理容量等问题后重新加载扩展，由已提交检查点恢复。

## 当前边界

- 抖音批量采集复用当前项目的登录态分页接口，目标为 1–999 条、批次间隔至少 10 秒，并同时识别两种企业认证字段。未加入旧版前台滚动采集的兜底路径。
- 励销云按已知企业名称精确补全，不作为行业/地区泛搜入口。平台匹配范围仍为首屏 10 条；无法唯一匹配时保留候选并标记部分完成。查询只依赖励销云登录态，与 CRM 独立。旧风鸟云任务不再发起请求。
- 企业认证和搜索命中只用于发现候选；近期活跃、主营业务、地区、企业主体及符合性仍需证据。励销云返回的联系方式直接作为可联系信息；联系人归属沿用来源标签，不额外发起本人核验。业务信息缺口仅影响业务匹配判断。
- 旧版只有摘要或截断缓存的会话标记为 `legacy_partial`，无法补回此前未保存的内容。
- 完整 JSON 备份包含业务关联，导入按记录标识补齐缺失数据及来源关联，保留本机当前字段、档案和回执，导入任务保持暂停。当前备份整包在内存中生成，单次导入上限 64 MB；大数据量的流式备份尚待扩展。验证参数不进入业务备份。
- 已预留稳定 ID、版本、事件序号和元数据入口；服务端同步尚未实现。
- 自动化测试使用 IndexedDB 与浏览器 API 模拟，不等同于真实平台登录态、验证码和 CRM 业务联调。视图检查由项目负责人进行。
